# 坐标系 / 朝向 / pose / 骨骼 roll

XPS→MMD 里「骨改完名、权重也对,但**一加动作就扭曲/手臂拧麻花/整体散架**」,根因往往不在骨名,而在**坐标系、朝向、初始 pose、骨骼 roll** 这四件没对齐。这页专门讲它们。

## 1. 坐标轴约定差异

| 环境 | 前 | 上 | 手系 | 备注 |
|---|---|---|---|---|
| **MMD / PMX** | **+Z** | +Y | 左手系 | 模型默认面朝 +Z(朝屏幕) |
| **Blender** | −Y(默认) | +Z | 右手系 | |
| **XPS / XNALara** | 多为 +Z 朝向、Y up | — | — | 来自各游戏,未必统一 |

- [[xps-tools-blender]] 导入时会做一次坐标转换;[[mmd_tools]] 导出 PMX 时再转一次。**中间不要手动再翻轴**,否则两次转换叠加 → 模型躺下/镜像。
- 症状:导出后模型在 MMD 里**躺平、面朝下、或左右镜像** → 多半是中途 Apply 了一个额外旋转。解决:让模型在 Blender 里**站立、面朝 −Y(Blender 前方)**,把旋转 **Apply 干净(旋转归零)** 再导出。

## 2. 朝向与 Apply Transform(最常见坑)

导出前,模型 Object 的 **旋转/缩放必须 Apply 归零**(`Ctrl+A → Rotation & Scale`):

- 没 Apply 缩放 → 物理炸开、IK 比例错乱(见 [[xps-to-mmd-流程]] ②)。
- 没 Apply 旋转 → MMD 里朝向错乱、动作方向反。
- Armature 和 Mesh **都要** Apply。

## 3. A-pose ↔ T-pose

XPS 模型常是 **A-pose**(手臂自然下垂约 30–45°);MMD 标准动作几乎都是按 **T/A 混合**(MMD 的「腕」基准角度有约定)做的。

- **关键不是 T 还是 A,而是「绑定姿势」要与目标动作的基准一致**。MMD 社区模型多数手臂下垂约 **35° 左右**(非纯水平 T)。
- 若 XPS 是纯 T 或角度差很大 → 加载动作后肩/腕基准偏移,出现「抬手过头/夹臂」。
- 处理:在 Edit/Pose 模式把手臂调到接近标准基准角度,再 **Apply as Rest Pose**(应用为静止姿势),让权重和骨向重新基于该姿势。
- 注意:Apply Rest Pose 后要重查权重,且物理刚体位置可能需要跟着移。

> 待补充/待核实:MMD「腕」标准基准的精确角度值(社区常引用约 30–40°);ingest 一份权威骨配置后给出确切数。范本 [[标准骨架范本-reika]] 可作角度对照。

## 4. 骨骼 roll(滚转轴)与扭转

这是「**手臂一转就拧成糖纸**」的隐藏原因:

- Blender 每根骨有 **roll(绕自身轴的滚转)**;XPS 导入后骨的 roll 常是乱的。
- roll 不一致 → 旋转轴方向错 → 加载动作时该骨绕错误轴转 → 扭曲。
- 尤其影响 **腕/ひじ/手首** 和 **腕捩/手捩**(扭转骨,见 [[准标准骨骼-semi-standard-bones]]):roll 错了,捩り分散直接失效。
- 处理:Edit Mode 选骨 → `Ctrl+N` 重算 roll(常用 Global +Z 或 View);手臂链让局部 X/Y 轴方向统一指向下一根骨。导出后在 [[pmxeditor]] 的 TransformView 逐轴测旋转验证。

## 5. 镜像对称

- 左右骨命名带 `左/右`(MMD)或 `_L/_R`(Blender),命名正确才能 **X-Mirror 编辑 / Mirror 权重**。
- XPS 模型未必严格对称;镜像权重前先确认左右骨位置镜像对齐。

## 自查顺序(出现扭曲时)

1. 模型站立、朝向对、**旋转+缩放已 Apply**?
2. 绑定姿势角度接近 MMD 基准?(A-pose 是否需 Apply Rest Pose)
3. 手臂链 **roll 是否统一**?(扭转麻花的元凶)
4. 左右是否对称、命名 L/R 正确?
5. 再回 [[xps-骨骼映射]] 查骨名(含全角/半角,见 [[标准骨架范本-reika]])。
